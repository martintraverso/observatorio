# Observatorio Uruguay — Implementation Plan for Claude Code
 
Read `SYSTEM.md` first (what the system is and its rules) and `ACCEPTANCE_CRITERIA.md` (how each part is judged). This plan is ordered: each milestone leaves the repo in a working, tested state. Do one milestone per branch/PR, and list the AC IDs it satisfies in the PR description.
 
## Working agreements
 
- Language: UI copy, table/column names and code identifiers in **Spanish**; comments may be Spanish or English.
- Never change the data rules in `SYSTEM.md` §4 without asking the maintainer.
- Keep phase-0 tests green at every step (AC-T1…T9).
- Prefer small, boring tools. No server, no paid service, no Docker requirement for local work.
- When a source detail is uncertain (file layout, column meaning), open the source's metadata (PDF/README) and write down what you found in the source's `fuentes/*.yml` notes. Do not guess.
- Ask the maintainer before: adding a new paid/third-party service, changing the territory id format, deleting data, or force-pushing.
## Starting point
 
The maintainer has `observatorio-fase0-codigo.zip` (repo) and the INE original `Unidades_Geoestadisticas_Censo_2023.zip` (~60 MB). Phase 0 works: `python pipeline/territorios_2023.py <zip>` → `datos/salida/`, then `pytest -q` (7 tests pass).

## M0 — Repository and CI
 
Goal: a clean GitHub repo where every push is linted and tested.
 
1. Unzip the phase-0 code into the repo root; commit as-is.
2. Add `pyproject.toml` (project metadata, ruff config, pytest config) keeping `requirements.txt` for Actions.
3. Add `.github/workflows/ci.yml`: Python 3.12, install, `ruff check`, `pytest -q`. Tests that need data must run after the pipeline; for CI, add a small **fixture**: a tiny GeoPackage subset (e.g. department 07 Flores with its sections and segments, plus 01 Montevideo barrios/CCZ) generated by a script `scripts/crear_fixture.py` from the real zip and committed under `tests/fixtures/` (keep it < 2 MB).
4. Parametrize tests so they run on the fixture in CI and on the full data locally (`OBS_DATOS=completo`).
5. Document in README how to upload the original zip to release `crudos` (`gh release create crudos <zip>`).
Done when: AC-A1; AC-T1…T9 tests pass on fixture in CI and on full data locally.
 
## M1 — Pipeline hardening
 
Goal: a reusable pipeline pattern for all future sources.
 
1. Extract shared code from `territorios_2023.py` into `pipeline/comun/` (sha256, capture records, writing Parquet/DuckDB, report writer, check runner).
2. Add `datos/salida/capturas_historial.parquet` (append-only across runs) and implement skip-if-unchanged (AC-P8).
3. Add determinism test (AC-P2) and the "no observation at unpublished level" check (AC-P5).
4. Make the fuentes registry richer: `estado`, `temas`, `nivel_mas_detallado`, `frecuencia`, `formato`; load all `fuentes/*.yml` into the `fuentes` table.
5. Add AC-T9 test (department totals equal INE department layer).
Done when: AC-P1…P9 and AC-T1…T9 pass.
 
## M2 — Web data build
 
Goal: everything the static app needs, as files.
 
1. `pipeline/web.py` builds `datos/salida/web/`:
   - PMTiles for `segmento` (and preferably all levels in one file with one layer per level) using **tippecanoe** (install in Actions via apt or build; locally optional — document it). Feature properties: `id`, `codigo`, `nombre`, `depto`.
   - Coverage-simplified GeoJSON for small levels (AC-W2).
   - `territorios_index.json` for search (AC-W3) with accent-folded `nombre_busqueda`.
   - `fichas/<nivel>/<codigo>.json` per territory (AC-W4): identity, parents chain, children ids by level, observations with indicator metadata and source reference.
   - `indicadores.json`, `fuentes.json`, `capturas.json`.
   - `manifest.json` (AC-W5).
2. Tests for sizes, coordinate precision, coverage (no gaps/overlaps between neighbours in simplified output), and that every territory has a ficha file.
Done when: AC-W1…W5.
 
## M3 — Data workflow and releases
 
1. Replace `fase0.yml` with `datos.yml`: manual + weekly; download originals from `crudos` (fallback to source URL); run all pipeline scripts; run tests; on success publish to release `datos` (all Parquet, DuckDB, `web.zip` or individual web files, report); on failure keep the previous release (AC-A3).
2. Write the report to the job summary.
Done when: AC-A2, AC-A3.
 
## M4 — App skeleton
 
Goal: a deployable static app with routing, layout and data loading.
 
1. Create `app/` with **SvelteKit + `adapter-static`** (prerender all territory routes from `territorios_index.json`, or use a SPA fallback page if prerendering 5,500 routes is too slow — measure and decide; record the decision in `app/README.md`). TypeScript. No UI framework beyond Svelte; plain CSS with design tokens from `SYSTEM.md` §8 in `app/src/lib/tokens.css`.
2. Data access layer `app/src/lib/datos.ts`: loads `manifest.json`, index, fichas; caches; one place to change the base URL (local `datos/salida/web` in dev, release/CDN in prod).
3. Global layout: header, nav (Mapa · Fichas · Datos · Fuentes), search box (empty), footer with license/attribution.
4. Formatting helpers for `es-UY` numbers and dates (AC-G1).
5. Deploy workflow `app.yml` to Cloudflare Pages (or GitHub Pages; ask the maintainer which account to use) triggered by changes in `app/` or a new `datos` release (AC-A4).
6. Add Playwright with one smoke test per route and axe-core checks (AC-G5).
Done when: app deploys; AC-G1, AC-G3 (route works on direct load), AC-A4.
 
## M5 — Search
 
1. Client-side search over `territorios_index.json` with accent/case folding; rank exact code > name prefix > contains; show level + parent (AC-S1…S3).
2. Keyboard navigation (↑ ↓ Enter Esc), ARIA combobox pattern.
Done when: AC-S1…S3, plus Playwright tests.
 
## M6 — Map screen
 
1. MapLibre GL JS map with PMTiles source; light, neutral base (or no base map, just boundaries on `#F6F7F5`); INE attribution.
2. Left panel: tema → indicador → nivel → período. Only phase-0 indicators exist now (Población: personas, hombres, mujeres; Vivienda: viviendas); other topics show the "Todavía no hay fuentes cargadas" state.
3. Choropleth with quantile classes on the 5-step blue ramp; legend with class breaks; derived indicators allowed only if computed in the pipeline (e.g. density = personas / area_km2 → add in M2 as a pipeline indicator, marked as derived).
4. Level-availability notice (AC-M2).
5. Selection → highlight + right panel with locator mini-map (simplified departments GeoJSON; ring for small territories) (AC-M3, AC-M4).
6. URL state (AC-M5); mobile bottom sheet (AC-M6).
Done when: AC-M1…M6, AC-G2, AC-G7.
 
## M7 — Fichas
 
1. Route `/territorio/[nivel]/[codigo]` rendering from `fichas/<nivel>/<codigo>.json`.
2. Department ficha: KPIs, locator, sections per topic, "Dentro del departamento" table (secciones / localidades / segmentos tabs), note on non-additive population (AC-F4), Fuentes de esta ficha, Cómo citar.
3. Section, locality, segment fichas: same template with level-appropriate blocks; segment ficha with "Más datos en los niveles que lo contienen" (AC-F3).
4. CSV download of shown values (AC-F5); citation (AC-F6); empty-topic notices (AC-F7).
5. Charts (pyramid, series) only when the data exists; none in phase 0 → render the empty state, not a fake chart.
Done when: AC-F1…F7.
 
## M8 — Fuentes and Datos screens
 
1. `/fuentes` catalog from `fuentes.json` + `capturas.json` with filters (AC-SRC1, AC-SRC2).
2. `/fuentes/[id]` detail with technical sheet, indicators and capture history (AC-SRC3, AC-SRC4).
3. `/datos` downloads page linking release `datos` assets with size, date, license, citation (AC-D1, AC-D2).
Done when: AC-SRC1…4, AC-D1…2.
 
## M9 — Quality pass
 
Lighthouse and axe on all routes; fix to reach AC-G5 and AC-G6; cross-browser and 390 px check (AC-G4). Update README with screenshots.

## Later phases (plan when M9 is done; confirm scope with the maintainer)
 
- **F1 — Census 2023 microdata** at segment level (age structure, households, education). First read INE's "Microdatos Censo 2023.pdf"; respect statistical disclosure rules stated by INE. (AC-X1)
- **F2 — ECH** department-level indicators (desempleo, actividad, pobreza) using survey weights; store only department/country (AC-X2). Consider the R package `ech` as a reference for variable definitions.
- **F3 — First point source** (e.g. road accidents or education centres) into `eventos` with point-in-polygon assignment (AC-X4).
- **F4 — 2011 geometries** + INE 2011–2023 correspondence table (AC-X3).
- **Zones** — if Marco Censal 2023 or INE (cartogra@ine.gub.uy) provides zone geometries, add `zona` under `segmento` (AC-X5).
